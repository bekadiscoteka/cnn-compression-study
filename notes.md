Two pipeline defects suspected, not a finding: (1) MinMax calibration lets a few outlier activations set the whole int8 range, which narrow pruned layers cannot afford; (2) QAT trained with moving-average ranges, but the exported model was recalibrated with MinMax, so the ranges QAT adapted to were thrown away.
2026-10-30 — Fix: calibrate_check.py picks the calibration method (MinMax or percentile 99.999 / 99.99 / 99.9) by the smallest mean int8 accuracy drop over all 12 fp32 models on 5,000 held-out training images, never the test set. Rule fixed before running; ties within 0.1 pp go to the simpler method. QAT now trains with activation ranges computed by the same rule on the same 500 calibration images, refreshed every epoch. Results of the re-run go to results_v2.csv; v1 is kept.

The ST runtime places activations in DTCM or AXI RAM automatically per model; this is part of real deployment and is reported, not controlled.
